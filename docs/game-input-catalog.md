# Game input and shortcut catalogue

Game Mode reads the shortcut assignments on the current Mac. Changing a shortcut in System Settings changes the keys shown by pikapik and the combination it handles when the game next comes forward.

`CopySymbolicHotKeys` supplies the operating system's catalogue size. The live SkyLight reader resolves each action's identifier, key, modifiers and enabled state. Discovery starts with the identifiers in the system's settings resources and saved preferences, then expands its search until the reported catalogue is covered. It includes unassigned actions and has no dependency on a particular default key combination. Names and categories come from the installed Keyboard Settings resources. Actions without a published name keep their identifier and current keys visible.

The catalogue on the development Mac contains 234 actions. The 201 assigned actions have 185 unique combinations; 33 have no assigned keyboard key. These numbers are a snapshot, and discovery runs against each user's Mac.

| Source | What is visible | What Game Mode does |
| --- | --- | --- |
| macOS symbolic shortcuts | Action, current key, modifiers, enabled state, category where published | Pauses the chosen action while its game is frontmost and restores its original state on leaving |
| Input source switching | The user's actual previous/next language combinations | Pauses the system menu and selects the input source directly for a deliberate shortcut, passing the key through to the game |
| pikapik's language gesture | The configured Option/Shift gesture | Allows a short deliberate gesture without a system picker; held game controls have priority |
| Other applications' event taps | Process, keyboard event mask, enabled state, filter or listener | Shows the owners separately; their private shortcut logic is not part of the macOS catalogue |
| App-specific menus, services and hardware-only handling | Not all assignments are available from the symbolic catalogue | Requires a separate adapter; this catalogue does not claim to enumerate those private handlers |

Follow Game Mode rules is the default for every action. It follows the existing general protection rules: protected actions that open windows or move focus are paused, and input-source actions can run in the background. A modifier chord is considered deliberate when it is short (up to 450 ms) and no other game key is held. Switch language on every press lets the user request language switching without that intent check. Disable in games pauses the macOS action while the game is frontmost; Allow in games permits its normal system behaviour, including windows and focus changes. Opening the dropdown shows a description beneath each option, with a checkmark beside the saved choice. The closed control shows just the selected name. Physical key-down and key-up events continue through the game input path. Only supported language actions offer the background choice; the stored automatic, pause, background and system values remain unchanged.

More game settings starts with eight stable topics. Each heading has a name, an explanation, an icon and a count, and its whole row opens the topic. Every action uses the same full-width IllustrationRow as Game safeguards and the other settings pages. Its name, useful additional detail, current keys and behaviour sit underneath. Descriptions that only repeat a clear action name are omitted. The layout stacks at narrow widths. Unassigned keys link to System Settings; their descriptions stay visible. The global settings search indexes live action names, descriptions, topics, identifiers and assigned keys. It accepts modifier symbols and names, combines words across fields and ranks exact key assignments first. Results show their topic and keys, use stable action identifiers, and open and highlight the exact action even when two names are identical. There is no separate search field on Games. The catalogue refreshes when settings opens and when the app becomes active. General Game safeguards are collected separately, with explanations for every switch.

Each catalogue action has a preview using the same game timeline, key caps and animation continuity as the original Game Mode previews. Unknown actions use an explicitly generic system-action preview. Empty published names fall back to a visible action identifier. Nested names keep their immediate parent topic for context.

Per-action choices are stored by action identifier in `game-mode-system-shortcuts`, included in settings backup and sync. Existing group rules remain the baseline for their known actions. A per-action choice takes priority. Emergency Force Quit stays available.

## Validation

`scripts/test-settings-search.swift` checks modifier aliases, phrases, ranking and the distinction between a key chord and Mission Control. `scripts/test-system-shortcuts.swift` checks search targets with duplicate names, localized language actions, discovery beyond the starting range, remapped keys, duplicate combinations, per-action choices, deliberate language input and held movement keys, and compares live discovery with the native catalogue. `scripts/test-game-language.swift` checks modifier release before and after the game observer updates its state, and protects held movement keys. pikapik’s own gesture does not depend on an assigned macOS input-source shortcut. `scripts/render-system-shortcuts.swift` renders the available preview families in light and dark. `scripts/dump-system-shortcuts.swift` writes an inspectable snapshot without committing user-specific key assignments.

The shortcut-link crash fixed in 1.30.14 was a separate issue: a lazy compact-map lookup read a changing accessibility row twice. The second read could return nil after the first had succeeded, triggering a Swift trap. The lookup now reads each node once, with a regression test for disappearing text.
